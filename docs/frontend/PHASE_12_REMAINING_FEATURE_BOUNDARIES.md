## Boundaries created

### `features/accounts` (repository, service, README)

`js/accounts.js` registers `A.ACCOUNTS` as `APP.data` source `accounts`, with functions that delegate at call time. This is the same pattern as Markets. It adds no storage and changes no persistence.

Consumers migrated:
- `workflow.js`: `accountFor` → `accounts.byTraderId`. In `wf-account-create`, the ID is now generated by `accounts.nextTraderAccountId(U.pad)` (same formula) and the record is added with `accounts.add`. Record fields, role, `marketScopes` and status are unchanged.
- `v-tieuthuong.js`: `ttLinkedAccount` → `byTraderId`; `tt-miniapp-toggle` → `setStatus`.

### `features/finance` (repository, service, README) — read only

- `unpaidInvoicesForContract(contractId)`: consumed by the liquidation precondition in `contracts/page.js` (2 places). The debt sum still uses `U.sum(…, U.due)`.
- `unpaidInvoicesForTrader(traderId)`: consumed by the "Khoản chưa thanh toán" count in both trader drawers.

No invoice, payment, debt, receipt or reconciliation computation was changed or moved.

## Dangerous cross-feature writes (documented, not changed)

1. `A.refreshStall(st)` (`core.js`), called from payment flows. Finance changes a business point's `status` between `thue` and `no`. Target: an explicit finance → business-points use case.
2. `mini.js` writes payments, bank entries, `pointRequests`, session records and notifications directly. Target: Mini App calls finance / point-change / session use cases.
3. Split/merge/conversion execution in `v-tieuthuong.js` writes `A.db.stalls`, `A.idx.stall`, contracts context and `directSellerAssignments`. Target: a dedicated point-change feature.
4. `syncExpiry` (`contracts/page.js`) creates notifications during render. Target: a scheduled/back-end job.
